# worklog

A self-hosted work/break timer with reports and an optional day planner. There are three front ends on one server:

- `worklog/`: the FastAPI server, which serves the JSON API (`worklog/web/api.py`) and the web UI (`worklog/web/templates`, `static/`)
- `qt/`: a Qt Quick client for desktop (Windows) and Android that talks to the same JSON API
- a Garmin Connect IQ widget (`garmin/`)

The Day/Week planner lives in `day/` and `balance/`; its host jobs are in `balance/jobs/`. Configuration: `docs/configuration.md`; optional host modules: `docs/host-integration.md`.

**Public repo:** never commit personal names, hosts, IPs, emails, paths or data. Personal values belong in config (env vars, `DAY_RULES`), and tests use the example household in `day/rules.example.json`. The pre-commit hook (`scripts/git-hooks/install.sh`) enforces a private deny list.

## Server

The run, test and Docker commands are in `README.md`. The app is created by `factory()`, and there is no module-level `app`.

- **Auth:** HTTP Basic on everything except `/healthz` (realm `worklog`). An unauthenticated request gets `401 {"error": "login required"}`.
- **Errors:** every error comes back as `{"error": "..."}` with a 4xx status, except an unexpected exception: 500 `{"error": "internal error"}`. `POST /api/blocks` and `PUT /api/blocks/{id}` refuse an end that is not after the start with 400 "end must be after start" (import still accepts such rows and flags them).
- **Contract:** the web UI (`static/app.js`, `static/pomodoro.js`) is the reference for client behaviour. The Qt app mirrors it, so a change to the API or to web behaviour usually needs the same change in `qt/`.
- **Store:** schema version 8 adds `blocks.start_fold`/`end_fold` (see DST below); version 7 added `timer_requests` (the `request_id`s already acted on) and the `currency` setting (1 to 4 characters, default the euro sign; in `/api/settings` and the full `/api/status`); version 6 added a unique index that allows one running block. Block writes, imports and the `at` check run under `_LOCK`. Import is one transaction; the dry run returns `would_delete_running`, the result `deleted_running`.
- **Timer routes:** `/api/start|pause|stop` accept `expect_state` (`working` | `break` | `stopped`) and answer 409 `{"error": "state changed", "state": ...}` on a mismatch; it is ignored when `at` is present. A replay with `at` after an auto-close extends the auto-closed block to `at` and clears its flag. A late-night split flags both parts `auto_closed` when the block started before `auto_close_time`. The full and the brief `/api/status` carry `resume` (the last work block's type and project, `worklog/status.py` `last_work_block()`; calendar-sourced meetings are skipped); break-type lists put `default_break_type` first.
- **Request ids and DST:** `/api/start|pause|stop` accept `request_id` (1 to 64 characters): a repeated id does nothing and answers the current status, and only a successful action is remembered. Elapsed time is true elapsed time across a DST change (`worklog/tzutil.py`). Schema version 8 adds `blocks.start_fold`/`end_fold` (1 = second pass of a repeated hour, NULL = first pass or not repeated; the timer sets them from the zone-aware clock, typed or edited times clear them, the visible `HH:MM` and the block JSON are unchanged). A block's `minutes`, the elapsed time and the day/report totals are true durations across the repeated hour (02:30 first pass to 02:10 second pass is 40 minutes), so closing there no longer ends early or flags `auto_closed`; the connection carries the zone (`db.connect(..., tz=)`) for this. An `at` inside the repeated hour means the later pass.
- **Clients, break types, undo:** `GET/POST /api/clients` and `PUT/DELETE /api/clients/{name}` (`{name, billable}`; DELETE is 409 while blocks or `default_client` use it); `GET/POST /api/break-types`, `PUT /api/break-types/{name}` (`{name}` renames it in the store, its blocks and `default_break_type`; 404 unknown, 400 empty, duplicate or used as a work type) and `DELETE /api/break-types/{name}` (409 for the default or a type in use). Break types are stored lower case. `POST /api/balance/blocks/{id}/propose` returns an approved or rejected block to proposed (the Week page's Undo).
- **Block shortcuts:** `POST /api/blocks` accepts `cut: true` (closed blocks only): a block of that day the new one lies inside is split in two, one it reaches into is trimmed, one it covers whole is left alone (overlap warning), and the running block gives way only when the new block is already over (what runs on is a new running block). `POST /api/blocks/{id}/merge-next` joins a block with the one that starts where it ends (409 when none does). The web's block rows have ⤒ merge (touching blocks with the same type, project, client and billable), ▶ start again and ✂ split (a dialog that POSTs with `cut`); the Qt app has a "same as above · Merge" seam row in `BlockList`, and Split… / Start again in `BlockDialog` (every new closed block it adds sends `cut`). The Timer's "at" field (web `#at-time`, Qt `atField`) backdates the next Start/Pause/Stop to that time today (`at`), and "Start from HH:MM" starts where today's last block ended. Up/Down in a time editor moves it 5 minutes, 1 with Shift (web `nudgeTime()`, Qt `TimeField.nudged()`).
- **Limits:** ranges are capped at 3660 days for `/api/summary`, `/api/days` and `/api/heatmap`, 7320 for `/api/export.*`; uploads at 10 MB (413). Every response carries `X-Content-Type-Options`, `X-Frame-Options: DENY` and `Referrer-Policy`. Auth runs PBKDF2 in a thread, at most 2 at once, and remembers a failed header for 60 s.
- **Web scripts:** `static/core.js` (`window.wl`, loaded before the page scripts) is the one fetch wrapper, server clock, stale-answer guard (`sequence()`) and in-flight lock (`locked()`); page scripts do not call `fetch` or the device clock directly. It also switches the parts of a page (`#views` buttons with `data-view`, parts with `data-pane`, `wl.showView()`): Week (Week · Goals · Load) and Day (Day · Work · Sync; the Sync label and the prep-note dialog are set in `day.js`). Start with nothing picked sends `status.resume`; Pause uses the picked break type, else the first of `break_types`, else no type (Qt follows the same rules). `/settings` holds Defaults, rate, week basis and the shortcuts toggle (`localStorage` key `worklog.shortcuts`). The navigation is one `<nav>` in two layouts: from 760 px the tabs at the top (Timer, Day, Week, Pomodoro, Reports, Expected hours, More with Add or find a date, Move an event, Work calendar, Settings); below 760 px the app's fixed bottom bar (Timer, Day, Week, Pomodoro, More), where More opens upward and also holds Reports and Expected hours (`wide-only`/`narrow-only`, `on-narrow` on the More button). The bar hides while a text field has the focus on a touch device, and the Undo bar sits above it. `/` always redirects to `/timer` (the site opens on the Timer, as the app); the Day page is `/day`, which redirects to `/timer` when the planner is not configured; the PWA starts at `/timer`. The header bar is the same width on every page (only the Day page's `main` is wider), the selected tab is not bold on the wide layout and `html` has `scrollbar-gutter: stable`, so the tabs never shift between pages.
- **Web offline, currency, idle:** every currency symbol comes from `wl.currency()` (kept in `localStorage` key `worklog.currency`, set from the settings and the full status); no literal symbol in templates or scripts. `/settings` also has Currency, a Clients card and a Break types card. Timer Start/Pause/Stop go through `wl.queue.act()` (`core.js`): each carries a fresh `request_id`; when the server cannot be reached the action is kept in `localStorage` (`worklog.queue`) with `at` (the server clock at the tap) and replayed in order at load, after any good answer, every 15 s and on `online`. The head stays on a network error, 401, 408, 429 and 5xx and is dropped on any other status (the message shows); new actions queue behind waiting ones; the Timer shows "N action(s) waiting - Retry now - Discard" (Discard confirms), the state the queue implies, and dimmed totals. Other mutations are not queued. The last full status (`worklog.status`) and day are kept so the Timer renders "Offline - last update HH:MM" without the server; every page shows that bar while requests fail. `/sw.js` (route in `pages.py`, source `static/sw.js`, cache name carries `STATIC_VERSION`, old caches removed on activate) serves pages and static files network first and from its copy only when the fetch throws; it never touches `/api/*`, and a 401 is passed on, never replaced by a kept page. The idle prompt (Timer only, while the page is open; `worklog.idle`, `worklog.idleMinutes`, default on, 60) asks once on return after the idle time while a work block runs, wording as in the Qt app; "Log as break" pauses at the idle start (not before the block's start) and starts the same type and project now, and a failed request keeps the question. The Week page's Undo calls the `propose` route.

## Qt app (`qt/`)

### Toolchain

Qt 6.12 (desktop kit plus the Android kits you need), CMake, and for Android the SDK, NDK 27, `android_openssl` and JDK 21. Set the paths below for your machine.

Build and lint outside Qt Creator (Git Bash). Use a build directory outside the source tree:

```sh
QT=<path to Qt>/6.12.0
cmake -S qt -B <builddir> -DCMAKE_PREFIX_PATH=$QT/<desktop kit>
cmake --build <builddir> -j8
cmake --build <builddir> --target all_qmllint   # must print no warnings
```

Windows release (MinGW kit): `qt/release.sh [outdir]` builds Release, bundles the Qt runtime with `windeployqt` and zips it (`tar.exe -a -c`) to `../worklog-release/WorkLog-<version>-win64.zip`. Run `WorkLog.exe` from that folder; the bare `appWorkLogApp.exe` in a build directory lacks the Qt DLLs.

Linux (Ubuntu 26.04, the system Qt 6.10 from apt):

```sh
sudo apt install qt6-base-dev qt6-declarative-dev qt6-declarative-dev-tools qt6-multimedia-dev \
  qml6-module-qtquick qml6-module-qtquick-controls qml6-module-qtquick-layouts qml6-module-qtquick-dialogs \
  qml6-module-qtcore qml6-module-qtmultimedia qml6-module-qtquick-templates qml6-module-qtquick-window \
  qml6-module-qtqml-workerscript libsecret-1-dev ninja-build libgl-dev
cmake -S qt -B <builddir> -G Ninja && cmake --build <builddir> && cmake --build <builddir> --target all_qmllint
```

- The Linux binary is `worklog` (`OUTPUT_NAME`). `qt/release-linux.sh [prefix]` builds Release, installs it with `linux/net.goldhoorn.worklog.desktop` (Exec rewritten to the full path) and the icons into `~/.local`, plus a trusted copy on the desktop (pass `-` to skip the install), and packs `../worklog-release/WorkLog-<version>-linux-<arch>.tar.gz`. The tarball doesn't bundle Qt.
- The many "qml plugin ... link target ... does not exist" CMake warnings come from Debian's Qt packaging and are harmless. The PipeWire `spaVisitChoice` lines at startup come from Qt Multimedia.
- qmllint 6.10 is stricter than 6.12 in places (e.g. `use-proper-function` on calling a `var` property).
- Qt 6.10 has no byte-array overload of `Qt.btoa()`: it encodes the array's text (`"97,98,…"`). `Api.base64()` encodes the Basic auth header in plain JS instead.

Android APK. Use `android_x86_64` and `-DCMAKE_BUILD_TYPE=Debug` for the emulator, because a debug APK is signed and installs with `adb install -r`:

```sh
$QT/android_arm64_v8a/bin/qt-cmake -S qt -B <builddir> -G Ninja -DQT_HOST_PATH=$QT/<desktop kit> \
  -DANDROID_SDK_ROOT=$ANDROID_SDK -DANDROID_NDK_ROOT=$ANDROID_SDK/ndk/<version> -DCMAKE_BUILD_TYPE=Release
cmake --build <builddir> --target apk   # android-build/build/outputs/apk/release/*-unsigned.apk
```

- A release APK has to be zipaligned and signed before it installs. For sideloading, the debug key is enough: `zipalign -f -p 4 in.apk out.apk`, then `java -jar build-tools/37.0.0/lib/apksigner.jar sign --ks ~/.android/debug.keystore --ks-pass pass:android`.
- If the first Gradle run hangs with no output, kill the stuck `java.exe` daemon and build again.
- The app's logs: `adb logcat --pid=$(adb shell pidof net.goldhoorn.worklog)`. Driving the app from the shell with `adb shell input tap x y` plus `adb exec-out screencap -p` works for screenshots.
- Right after the emulator boots, the first requests can fail with "Cannot reach". That's the emulator's network starting up, not TLS.

- The executable is a GUI app (`WIN32_EXECUTABLE`). To see `console.log` and QML warnings on stderr, set `QT_FORCE_STDERR_LOGGING=1`.
- If the app is running, the linker can't overwrite `appWorkLogApp.exe` ("Permission denied"). Close it first, or build into another directory.

### Offline queue

`Api.timerAction(path, body, onOk, onErr, onQueued)` is what Start/Pause/Stop use (it gives every action a fresh `request_id`, sent with the first try and kept in the queue for every replay, so a request that timed out after the server applied it is not applied twice: the server answers a repeated id with the current status), on the Timer page and from the tray and hotkey. (The Pomodoro's log actions and the idle question's pause use `Api.request`: a queued action is stamped with the time it is queued, which would be wrong for a pause dated in the past.) When the server cannot be reached (status 0) the action is queued in order with `at` (the server's wall clock when it was tapped, `Api.atNow()`), kept in `Settings` category `offline` with its `request_id`, and replayed by `Api.flushQueue()`: after any answer from the server, every 15 s while queued, and at start-up. The server accepts `at` on `/api/start|pause|stop` (never in the future, never over 24 h old, never before the running block's start). An action the server refuses on replay is dropped (see `flushVerdict`) and `Api.queueFailed(message)` fires. Block edits, deletes and the other requests are not queued. `setServer()` returns an error string ("" on success) and drops the queue when the URL or user changes (`dropQueue`). `flushVerdict(status)` decides the queue head's fate: it stays on 0, 401, 408, 429 and 5xx (`queueStuck` says why it is stuck) and is dropped on any other status. A generation counter (`queueGen`) keeps a new queue safe from a flush still in flight. A request made while the app is locked fails with status 0, so the queue keeps its actions until `unlock()`.

### How refreshing works

- `Api.status` is the one shared copy of `/api/status` (with `Api.statusAt`, `Api.statusError`). Api fetches it at start, after every mutation, on a server change and every 30 s; `Api.refreshStatus(then)` asks for a fresh one (`then(status, error)`, concurrent calls share one request). The Timer, the Pomodoro, the Log's chips, the tray and the idle question read it; none of them polls on its own. It keeps its last value while the server is unreachable, and `Api.online` says whether the last request got an answer.
- `Api.changed()` fires after every successful non-GET request. The visible page reloads on it; a hidden page reloads when its tab is shown.
- `Api.serverChanged()` fires when the URL or login changes.
- Pages reload when their tab becomes visible, so a failed load never sticks. The Timer also reloads every 60 s while visible.
- Pages that can be asked for another week, month or grouping count their requests and drop an answer that is no longer the newest.
- Deleting a block (BlockDialog) is immediate; the page's Snackbar offers Undo, which POSTs the block again (billable restored with a PUT if the client default differs).
- Mutations of the running block send `require_open: true`, as the web does. A stale snapshot gets a 409 instead of retyping a block that has already closed.

### QML pitfalls hit here

- **Don't name properties after built-in Item ones.** Each of these broke a load or lint here: `state`, `scale`, `data`, `top`. (`top` passed qmllint but failed at runtime with "Cannot override FINAL property".) Use names like `timerState`, `maxH`, `summary`, `headerH`.
- **A nested layout is never wider than its children allow.** `Layout.fillWidth` on a Row/ColumnLayout does nothing if no child can grow. Centred labels need `Layout.fillWidth: true` plus `horizontalAlignment: Text.AlignHCenter`, not `Layout.alignment: Qt.AlignHCenter`.
- Files with delegates use `pragma ComponentBehavior: Bound` and qualify everything (`row.modelData`, `root.x`), so qmllint stays clean.
- Repeater models that mix item kinds (BlockList's gap rows) must guard fields that are missing: `!!x.flags`, `x.type || ""`.
- A `Popup` is not an Item: `Keys.*` cannot attach to it. Put key handling on its `contentItem`.
- Window `Shortcut`s still fire under a modal dialog when focus is on a non-text control. Disable them while the page's dialog or picker is open.
- A callback given to `Api.refreshStatus()` or `Api.request()` can run after its page was destroyed (the tests do this): start it with `if (!page) return`.
- Number fields: never `DoubleValidator` plus `Number(text)`. Both follow the device's locale differently, so a decimal-comma locale rejects "7.5" and turns "7,5" into NaN. Use a `RegularExpressionValidator` accepting `[.,]` and `Api.parseNum()`.
- A JS reserved word as an object key must be quoted (`"import": …`), or qmlcachegen fails.
- Don't name a property `window` in a component used under `Main.qml` (its `id: window` shadows it); `appWindow` is used.
- Text that does not wrap, or a plain `Switch`, inside a `Card` is as wide as its single line and runs off a 320 dp screen (the card itself stays as wide as the page): give it `wrapMode: Text.Wrap` and `Layout.fillWidth: true`, use `AppSwitch`, and put fields side by side only above ~420 px (a `GridLayout` with `columns: availableWidth < 420 ? 2 : 4`).
- Don't name a property `on` + capital letter (`onToday`): QML takes it for a signal handler, the property reads as undefined and nothing warns. Use `isToday`.

### Tests

`qt/tests/` holds Qt Quick tests (`tst_*.qml`) that run against the real server on a throwaway database. Build with `-DWORKLOG_TESTS=ON` and run them with a Python that has the server's dependencies (on Windows also `tzdata`, or the server cannot load its timezone):

```sh
cmake -S qt -B <builddir> -G Ninja -DCMAKE_PREFIX_PATH=$QT/<desktop kit> -DWORKLOG_TESTS=ON
cmake --build <builddir> --target tst_worklog
python qt/tests/run_tests.py <builddir>      # starts uvicorn on a free port, runs tst_worklog offscreen
```

The test executable is built from the same `WL_QML_FILES`/`WL_SOURCES` lists as the app, so register a new file once, in `qt/CMakeLists.txt`. `tst_pages.qml` fails on any QML warning while a page loads. The tests use their own settings store, so the saved URL and login are never touched. On Windows the test exe is a GUI program: `run_tests.py` reads its result file, not stdout. `run_tests.py` gives the server a balance store and `DAY_RULES=day/rules.example.json`, so the Week and Find pages answer. `tst_review.qml` covers the review fixes; `tst_planner.qml` the Move dialog, timer row, "work on this", the PDF upload (`sample.pdf`, `notapdf.pdf`; `run_tests.py` gives the server a `WORK_CALENDAR_INBOX`), the break-type rename and the Back logic (it builds a `Main` with `Api.trayCapable` switched off: the tests run on a `QGuiApplication`). Every `tst_*.qml` in `qt/tests/` is picked up without registering it. Pure logic is kept in functions the tests call directly (`BlockDialog.changedFields()`, `QueueState`, `DatePicker.monthGrid()`, `TrayController.toggleRequestFor()`, `IdleWatcher.shouldAsk()`, the Settings URL helpers). `.github/workflows/qt.yml` runs build, qmllint and these tests on Linux.

### Android specifics

- **Widget, Quick Settings tile, ongoing notification:** native Java that calls the server itself (`HttpURLConnection`, Basic auth, always `?brief=1`), so it works while the app is closed. URL and user come from the SharedPreferences `worklog_widget` that the app fills through `TimerWidget.configure()` (QSettings' file is not meant to be read from Java); the password is `SecretStore.get(ctx, "password")`, the same ciphertext the app reads. The widget's and the notification's buttons are broadcasts to `TimerWidget` (a receiver that does the call on a thread under `goAsync()`). Start sends the brief `resume` (last work block's type and project), Pause the first of `breaks`; the tile stops a working block and otherwise starts. The elapsed time counts on the device (`Chronometer`, `setUsesChronometer`); the status is fetched again after actions, on the widget's 30 min update period, on an inexact 10 min alarm while a block runs, and when the tile is shown (at most every 30 s). The last status is cached in the same preferences for the tile. The notification shows only while a block runs. Every action fetches a fresh status first and skips a pointless one (Start while working, Stop while stopped); the tile decides stop or start from that fresh status, so a timer started elsewhere is never split. Actions tapped while the server is unreachable are queued in the same preferences (`queue`) with `at` and replayed in order before the next call; `at` is the server's clock, from an offset learned from the brief status's `now`. The widget, tile and notification then show "N action(s) waiting". This queue is separate from the app's own. All calls of one broadcast share an 8 s budget and `finish()` is forced at 9 s, inside `goAsync()`'s limit. Testing without a widget: `adb shell run-as net.goldhoorn.worklog am broadcast --user 0 -n net.goldhoorn.worklog/.TimerWidget -a net.goldhoorn.worklog.START` (also `PAUSE`, `STOP`, `REFRESH`, `TOGGLE`). The budget starts when the widget's run starts; a tap that cannot start with 2 s left is dropped with "Busy: tap again", never queued as offline. A refusal notice persists (prefs `notice`) until a successful action or the app opening. `SecretStore` tells "nothing stored" from "could not decrypt" ("Open Worklog to sign in again"). The break state reads "On break". `BootReceiver` (`BOOT_COMPLETED`, `MY_PACKAGE_REPLACED`) re-renders the widget and re-arms its alarms.
- **Biometric unlock:** Settings' "Require fingerprint/face to open" (shown only on Android when `Biometric.isAvailable()`; switching it on asks once first) is `Api.requireUnlock` in Settings. At start Api then stays `locked`: it does not read the password, `request()` fails with "Locked", and `Main.qml` covers the window with a lock screen that asks at once and has an Unlock button. `Api.unlock()` reads the password and fires `serverChanged()`, so every page loads. It uses the platform `BiometricPrompt`, not `androidx.biometric`, because the androidx prompt needs a `FragmentActivity` and Qt's activity is a plain `Activity`; so there is no extra Gradle dependency. Android 9 has no screen-lock fallback, so it reports unavailable there. The app locks again when it comes back after more than 2 minutes in the background (`Api.relockAfterMs`; `Api.lock()` clears the password from memory). The widget, tile and notification are not locked. A screen lock on the emulator: `adb shell locksettings set-pin 1234` (and `locksettings clear --old 1234`); the prompt is a secure window, so `screencap` shows it black.
- **Pomodoro notification:** every `save()` in `PomodoroPage` schedules an exact `AlarmManager` alarm at `endsAt` (`USE_EXACT_ALARM`), or cancels it. `PomodoroAlarm` posts the notification even when the process was killed, and tapping it reopens the app. `POST_NOTIFICATIONS` is requested when `Notifier` is first used. The end time is also kept in prefs `worklog_pomodoro` and `BootReceiver` restores the alarm after a reboot.
- **LAN servers on Android 17 (API 37):** an app needs the runtime permission `ACCESS_LOCAL_NETWORK` to reach a private address; without it every connect times out. It is declared in the manifest and asked for (with the notification permission) only when the saved server is a local address. On an emulator: `adb shell pm grant net.goldhoorn.worklog android.permission.ACCESS_LOCAL_NETWORK`.
- **Backups are off** (`allowBackup="false"` and `res/xml/no_backup_rules.xml`): the encrypted password is useless without its Keystore key, and the widget's cache is device state.
- **Local addresses:** `LocalNet.isLocalHost` is the one rule (RFC 1918, loopback, link-local, CGNAT 100.64/10, IPv6 ULA and link-local, `.local`, single-label names). Credentials are never sent over `http://` to a non-local host; the widget says "Server needs https: open Worklog".
- **Back key:** Qt 6.12 delivers Back to QML as `Key_Back` and never calls `Window.onClosing` for it, so `Main.qml` handles it where it arrives: `goBack()` (to the Timer from any other screen, `false` on the Timer so the system sends the app to the home screen). Three layers: a `Shortcut { sequences: ["Back"] }` (an application shortcut sees the key wherever the focus is; enabled only on Android, off the Timer, and not while a popup holds the focus, because an open menu/dialog/picker closes itself on Back (`inOverlay()` of `activeFocusItem`)); `keyHost`, a `FocusScope` around the pages with `Keys.onBackPressed`/`Keys.onReleased`; and the header and tab-bar buttons use `focusPolicy: Qt.NoFocus` on Android and `onActiveFocusItemChanged` puts a lost focus back on `keyHost`, so a tap never leaves the key without a handler. `onClosing` keeps the same `goBack()` for a close request and the desktop tray/quit path. Not verified on a device: only `goBack()`, `inOverlay()` and that `"Back"` parses to `Key_Back` are tested.
- **Keyboard:** the activity has `android:windowSoftInputMode="adjustResize"`: the window shrinks to what is above the keyboard and `Qt.inputMethod.keyboardRectangle` is then real. (With `adjustNothing` on API 37, edge to edge, that rectangle was only the 24 px navigation bar, so nothing could keep a dialog above the keyboard.) `AppDialog` keeps every dialog (BlockDialog, the planner/settings/week/idle dialogs) inside the room between the top inset and the keyboard with scrolling content, and a focused field is scrolled into view when the keyboard takes room (`ScrollBody`, and `BlockDialog` for its own Flickable). `Main.qml` hides the tab bar while the keyboard is up (`keyboardUp`) and `revealFocus()` scrolls the page's Flickable to the focused field (`keyboardOverlap` stays as a fallback for a window that is not resized), and the DatePicker hides the keyboard when it opens. Verified on the API 37 emulator (Timer block dialog, Week add form, Settings, Find, rename dialog).
- **Edge to edge:** Android 15 and later draw under the status and navigation bars. `Main.qml` pads the tab bar and the pages with `SafeArea.margins`.
- **Settings is under the bottom bar's More menu** (More then looks selected). The app opens on Settings when no user is saved, and any `NoticeBanner` showing `Api.loginMessage` gets a Settings button (`Api.settingsRequested()`).
- **Touch targets:** the billable toggle in `BlockList` is 40 x 40 dp; interactive components carry `Accessible.name`/`role`.
- **Narrow screens (320 dp):** a Material `SpinBox` needs about 150 px to show two digits, so grids of SpinBoxes go to one column below 360 px.

## Garmin widget (`garmin/`)

A Connect IQ widget with a glance for the Forerunner 965 (Monkey C). Build, test, simulator and sideload commands are in `garmin/README.md`.

- **Toolchain:** Connect IQ SDK 9.3, Java 21 and a developer key outside the repo (keep using the same key). Devices come from the SDK Manager.
- **API:** the watch only uses `?brief=1` on `GET /api/status` and `POST /api/start|pause|stop` (`_brief` in `worklog/web/api.py`). Without `brief` the responses must stay unchanged. The brief answer also carries `now` (the server's wall clock), which the Android widget uses to stamp queued actions; the watch ignores it. Start sends `resume` (the last work block's type and project), so a start after a break continues the same project.
- **HTTPS:** the real watch refuses plain `http://`. `Logic.hasLogin` allows `http://` only for `127.0.0.1`/`localhost` (the mock, `garmin/tools/mock_server.py`, with the simulator's HTTPS check off).
- **Glance code:** everything the glance uses carries `(:glance)`. Unit-test helpers that are not tests carry `(:debug)`, because a `(:test)` function must take exactly one `Logger`.
- **Glance cache:** the last brief status is kept in `Application.Storage` key "glance" (written by `WorklogClient`). The glance shows it at once and marks it " ?" when older than 10 minutes.
- `monkeydo.bat` takes Windows flags (`/t`); run it from PowerShell.
- **Key press and release can reach two views:** the press that opens the action menu was also selecting its first item, and the tap on an item reopened the menu. `MainView.markNav()`/`settled()` drop selects within 500 ms of the menu opening or closing. Keep that guard when changing the menu flow.
- **Actions:** they send `expect_state`; a 409 shows "Changed elsewhere", re-fetches and never retries. The widget refreshes every 60 s while open, redraws on a 10 s tick, and a 30 s watchdog clears `busy`. `ClientDone` callbacks take a third argument (the code) and `Logic.actionLabel` takes the state. Error texts: "Needs https://", "Login required", "No phone link", "Timed out", "Server error".
- **Simulator:** saved settings (`%TEMP%\com.garmin.connectiq\GARMIN\APPS\SETTINGS\*.SET`) override `properties.xml` defaults. With *Use Device HTTPS Requirements* ticked, `http://` fails with -1001. The simulator never times out a request. Enter is Select; arrow keys don't move menus.
- Private methods can't be named after a Toybox symbol checked with `has` (e.g. `vibrate`): the compiler warns.
- **Login on the watch:** sideloaded apps don't appear in the Connect IQ phone app, so settings can't be edited there. Build with `-f "garmin/monkey.jungle;garmin/local.jungle"`; `local.jungle` (git-ignored, from `local.jungle.example`) replaces `resources/properties/` with the git-ignored `garmin/local/properties.xml` holding the login. Never commit either.
- **Another device:** one `<iq:product>` line in `manifest.xml`, plus a simulator check and a launcher icon at the device's size.
